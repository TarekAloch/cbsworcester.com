# cbsworcester.com

The new website for **Complete Billing Solutions** — a family-run medical billing company in Worcester, MA. They've been taking care of mental-health providers since 2000, and the site needed to look like it.

**Live:** [cbsworcester.com](https://cbsworcester.com)

![Complete Billing Solutions homepage](./docs/portfolio/homepage.jpeg)

---

## The quick story

I built this with three goals: **fast**, **secure**, and **cheap to run forever**. It's a static site generated by [Astro](https://astro.build/), sitting behind Cloudflare, served from a small nginx box on Ubuntu. No app server, no database, nothing to break at 2am.

Here's how it landed:

- 🔒 **A+ on Qualys SSL Labs**
- 🛡️ **A on SecurityHeaders** (up from D before I started)
- ⚡ **100 on Lighthouse Performance**
- ✉️ **SPF + DKIM + DMARC** all live — the domain can't be easily spoofed

## The stack

- **[Astro](https://astro.build/)** for the site — static site generator, no runtime
- **[AstroWind](https://github.com/onwidget/astrowind)** as the starting template (MIT, credit preserved)
- **[Tailwind CSS](https://tailwindcss.com/)** for styling
- **[Cloudflare](https://www.cloudflare.com/)** in front of everything — DNS, CDN, TLS, WAF, bot protection, and the source of the security headers
- **nginx** on an Ubuntu VPS — the origin server, deliberately minimal
- **[Zoho Mail](https://www.zoho.com/mail/)** for outbound email, with proper auth
- **[Formspree](https://formspree.io/)** handling the contact form so I don't have to run a backend for it

## How a request actually gets served

```
Browser
   ↓
Cloudflare  —  TLS termination, security headers, bot mitigation, cache
   ↓
nginx on Ubuntu  —  HTTPS-only, TLS 1.2/1.3, static file serving
   ↓
Static files  —  built by Astro, sitting on disk
```

The origin nginx has no security headers in it. Not a mistake — Cloudflare handles that at the edge, and I wanted one place to manage the policy.

The Ubuntu host also runs a T-Pot honeypot for security research. That world is kept isolated from the production sites with a separate nginx instance inside Docker, different ports, different network boundaries. Full write-up in [`docs/infrastructure.md`](./docs/infrastructure.md).

## Security posture

### Headers: D → A

Before hardening, SecurityHeaders gave the site a D. After turning on the right Cloudflare response-header rules, it's an A — and it's actually a bit more than A, because the site also returns the cross-origin isolation headers (COEP / COOP / CORP) that most A-graded sites don't bother with.

Exact values and the before/after report are in [`docs/security-headers.md`](./docs/security-headers.md).

### TLS: A+

Certificate, protocol support, key exchange, and cipher strength all max out on SSL Labs. TLS 1.2 and 1.3 only. HSTS on with 180 days. HTTP/2 and HTTP/3 (QUIC) both live. That's all Cloudflare — one of the real benefits of putting them in front.

### Email authentication

SPF says "only Zoho sends for this domain." DKIM signs every outbound message with a real RSA key. DMARC is in monitoring mode (`p=none`) with aggregate reports going to Cloudflare's DMARC service — that's the right way to roll out enforcement, because flipping straight to `p=reject` is how you accidentally break your company's email for a week.

Records and verification commands in [`docs/email-authentication.md`](./docs/email-authentication.md).

### Performance

Static files + a CDN + immutable asset hashes = Lighthouse 100 on desktop, basically for free. The hard work was making sure nothing on the page blocked rendering; Astro does most of that for you if you let it.

## Running it locally

```bash
npm install
npm run dev       # http://localhost:4321
npm run build     # builds to ./dist
npm run preview   # preview the production build locally
```

Other scripts:

| Command | Does |
|---|---|
| `npm run check` | Type-check + Astro diagnostics |
| `npm run fix` | Prettier + ESLint with auto-fix |
| `npm run astro <cmd>` | Anything the Astro CLI can do |

---

## Deploying

1. `npm run build` → static output in `./dist/`
2. `rsync` that to the origin's nginx document root
3. Done. Cloudflare picks up the change on its next fetch.

No app restart, no staged rollout. One of the nice things about static.
